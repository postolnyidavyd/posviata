# ТЗ: Пульт ведучого «Посвята в ІТшника»

Веб-застосунок для проведення командного івенту (3 команди: **Mac / Linux / Windows**).
Ведучий керує всім з одного пульта; команди й проектор бачать свої екрани.

---
## ВАЖЛИВО
Аудиторія: івент для першокурсників ФІТ. Це визначає складність контенту в усіх конкурсах зі словами/питаннями. Слова для «Поясни це програмісту» та «Хто я? (IT Edition)», а також питання фінальної вікторини мають бути прості й загальновідомі — базові IT-терміни й побутові речі, які знає новачок на першому курсі, а не вузькі/просунуті поняття. Мета — щоб грали й веселились усі, а не тільки ті, хто вже шарить. Банки слів/термінів/питань наповнювати з цим прицілом.


## ⚠️ Параметри — погоджено

Всі бали також можна **редагувати вручну** ведучим у будь-який момент — це стартові числа. Всі значення нижче — конфіг, змінюються в одному місці (`config` / `.env`), щоб легко правити без переписування коду:

| Що | Значення | Статус |
|---|---|---|
| Keyboard Battle — бали за місце | 3 / 2 / 1 | ✅ погоджено |
| Paint it! — бали за місце | 3 / 2 / 1 | ✅ погоджено |
| Хто я? — бали за місце | 3 / 2 / 1 | ✅ погоджено |
| Поясни програмісту — бали за місце | 3 / 2 / 1 | ✅ погоджено |
| Keyboard — штраф за помилку | 3 (умовні секунди на помилку) | ✅ погоджено (легко міняється в конфігу) |
| Фінал — стеля ставки | 3 бали (макс на питання) | ✅ погоджено |
| Фінал — виграш / програш | **+ставка / −ставка, але не нижче 0** | ✅ погоджено |

Все це — конфіг, змінюється в одному місці (див. `config`).

## 1. Архітектура

- **Бекенд:** Node.js + WebSocket(будь-яка бібліотека яка підходить), один процес, хостинг **Railway**
- **Стан:** in-memory (об'єкт `Room`) — джерело правди
- **Persistence:** снапшот стану у файл при кожній зміні балів/розподілу; при старті процесу — відновлення з файлу (Postgres НЕ використовуємо — деплою під час гри не буде)
- **Фронт:** React (SPA)
- **Без акаунтів.** Ролі — через URL + секретний ключ кімнати

### Ролі (визначаються URL, не логіном)
| Роль | URL | Права |
|---|---|---|
| `host` | `/host?key=СЕКРЕТ` | повний стан + керування всім |
| `screen` | `/screen?room=ID` | повний стан, тільки перегляд (проектор) |
| `team` | `/team?room=ID&team=N` | **урізаний** стан, тільки відповідає |

**Критично — авторитет на сервері:**
- сервер приймає керуючі команди **тільки від `host`** (перевірка ключа). Повідомлення від `team` з керуванням — ігноруються
- сервер шле кожній ролі **свою версію стану**. `team` НЕ отримує: результат колеса до reveal, правильну відповідь фіналу до reveal, приховані слова конкурсів. Фільтрація **на сервері**, не на клієнті (інакше видно в DevTools)

### Реконект
- при вході `team` отримує `teamToken`, зберігає в `localStorage`
- при перезавантаженні/обриві — шле токен назад, сервер повертає в ту саму команду
- стан кімнати переживає рестарт процесу (снапшот)

## 2. Модель стану

```
Room {
  id
  hostKey
  mode            // поточний режим (див. нижче)
  teams: [
    { id, name, os, members[], score }   // 3 команди
  ]
  timer            // { running, secondsLeft, label }
  // дані активного режиму:
  wheel:    { spinning, result }
  keyboard: { reference, submissions[] }   // еталон + результати команд
  word:     { current, hidden }            // слово для Paint/Поясни
  final:    { question, bets{}, answers{}, revealed }
            // question = { text, type: 'single'|'open', options?[], correct }
            // для 'open': host вручну зараховує кожну відповідь на reveal
}
```

### Режими (`mode`) — host перемикає
| mode | що робить | realtime? |
|---|---|---|
| `lobby` | очікування | — |
| `wheel` | колесо розподілу | ні (автономно в host) |
| `keyboard` | Keyboard Battle | **так** |
| `word_reveal` | приховане слово для Paint / «Поясни» | напів (тільки host бачить слово) |
| `final_bet` | фінал-вікторина на ставках | **так** |
| `scoreboard` | табло | — |

> Додати новий конкурс у майбутньому = додати новий `mode`. Це переюзабельний скелет під наступні івенти.

## 3. Наскрізні елементи (є завжди, поверх будь-якого режиму)

### 3.1 Табло балів
- 3 команди з поточними балами, велике й читабельне (для проектора)
- host може **+/− будь-яку кількість балів будь-якій команді вручну** (бо більшість конкурсів офлайн — Paint, Хто я?, Поясни — судить ведучий)
- швидкі кнопки «+бали за місце»: обираєш конкурс → тиснеш 1/2/3 місце командам → нараховує 3/2/1

### 3.2 Таймер
- host запускає/паузить/скидає, задає час і підпис
- відображається на `screen` і `team`
- пресети під конкурси (10 хв, 15 хв тощо)

## 4. Режими детально

### 4.1 Колесо розподілу (`wheel`)
- host заводить список імен усіх учасників
- по одному: сідає учасник → host крутить → колесо зупиняється на MAC / LINUX / WINDOWS
- **зважений розподіл (важливо):**
  - ліміт на команду = `ceil(всього / 3)` (для 15 → 5)
  - вага команди = `ліміт − скільки вже в ній`; заповнена → вага 0 (колесо туди не докидає)
  - шанс сектора = вага / сума ваг
  - результат: команди рівні, різниця максимум 1; візуально виглядає як чесний рандом
- **фільтрація:** поки крутиться, `team` бачать плейсхолдер («Шляпа обирає...»)
- в `screen` показуєтья колесо вибору що крутиться
- анімація колеса — базова з назвами команди 

### 4.2 Keyboard Battle (`keyboard`)
**Механіка конкурсу:** 3 команди, у кожної 1 ноут (team-екран). Всередині команди всі крім одного читають з паперових папірців (укр слова, написані англ буквами — читають правильно українською), 1 друкує українською в поле. Всі команди друкують **одночасно** за сигналом.

- host задає **еталонний текст** (те, що має вийти) наперед
- host дає старт → таймер пішов, поля на team-екранах активні
- команда друкує → тисне «Готово» → сервер фіксує **час** + **текст**
- сервер рахує:
  - **час** фінішу (автоматично, безспірно)
  - **помилки** — помилка однієї букви в слові - одна помилка, 2 букви - теж одна помилка, не більше 1 помилки на слова, розділові знаки ігноруємо пропускаємо або видаляємо з кінцевого тексту бо якщо команда забула кому, все полетіло, я б також нормалізував текст типу щоб "слово" і "Слово" було одинаково
- на host-екрані: по кожній команді час + пораховані помилки + введений текст поруч з еталоном + **поле корекції** (ведучий затверджує фінальне число помилок вручну)
- ранжування: підсумковий_час = реальний_час + (кількість_помилок × штраф). **Штраф = 3** (стартове значення, винесене в `config`/`.env` — легко міняється за потреби)
- бали 3/2/1 за місце → в табло

### 4.3 Приховане слово — Paint / «Поясни» (`word_reveal`)
Обслуговує ДВА офлайн-конкурси одним режимом.
- банк слів заведений наперед (окремо для Paint — прості предмети; для «Поясни» — побутові речі)
- host тисне «наступне слово» → слово показується **тільки на host-екрані** (і опційно на екрані художника)
- `team`/`screen` бачать плейсхолдер + таймер (щоб не спалити слово)
- бали ставляться вручну через табло (судить ведучий)

### 4.4 Хто я? (IT Edition)
- **не окремий realtime-режим.** У застосунку — тільки **банк IT-термінів** (щоб ведучий не вигадував на ходу)
- сама гра офлайн (картки на лоб), бали вручну через табло

### 4.5 Фінал — вікторина на ставках (`final_bet`)
**Замінює «Збери ПК».** Кульмінація, перевертає таблицю.

- вікторини на початку гри НЕМА — команди приходять у фінал з балами з конкурсів
- потік на кожне питання:
  1. host показує питання → воно на `screen` і `team`
  2. кожна команда зі свого ноута **ставить від 1 до 3 балів** (не більше, ніж має; не можна піти нижче 0)
  3. команди дають відповідь (варіанти або відкрита — див. нижче)
  4. host тисне reveal → показується правильна відповідь + що поставила/відповіла кожна
  5. вгадала → **+ставка** (макс +3), не вгадала → **−ставка** (мінімум 0)
- рахунок **видно всім** під час фіналу (щоб аутсайдер міг свідомо ризикнути — тактика)
- банк фінальних питань наперед
- **тип питань: підтримуємо ОБИДВА типи** (кожне питання в банку має свій `type`):
  - `single` — single-choice (варіанти): команда обирає варіант, сервер судить автоматично на reveal
  - `open` — відкрита відповідь: команда друкує текст; автосудити ненадійно, тож **на reveal ведучий вручну позначає, хто вгадав** (host бачить всі відповіді + кнопку «зараховано/ні» по кожній команді), далі система нараховує +/−ставка
  - типовий фінал — мікс: одне `single`, одне `open`, за потреби ще пару

## 5. Дизайн (поки загально)

- **НЕ фінальний дизайн.** Зроби чисто, читабельно, з CSS-змінними для теми — щоб потім легко підмінити на дизайн-систему Студради ФІТ
- напрямок бренду (застосуй як стартові токени, без кастомних асетів):
  - основний акцент — фіолетовий (violet/purple)
  - фон — світло-сірий з ледь помітною текстурою (або просто чистий сірий)
  - акцентний шрифт — моноширинний (код-вайб) для заголовків/лейблів
  - загальна естетика — технічна, гіківська
- **всі кольори/шрифти — через CSS-змінні** (`--accent`, `--bg`, `--font-mono` тощо), в одному файлі теми
- `screen`-екрани (проектор) — крупний шрифт, високий контраст, читається здалеку
- місця під асети (іконки ОС, декор) — заглушки/плейсхолдери, підміню пізніше

## 6. Пріоритет реалізації

1. **Скелет:** WS-сервер, `Room` + перемикання `mode`, ролі host/screen/team, серверна фільтрація стану, снапшот у файл, реконект по токену
2. **Наскрізне:** табло балів (ручне +/−, кнопки за місце), таймер
3. **Режим `keyboard`** (три team-поля, збір час+текст, Левенштейн, корекція, ранжування)
4. **Режим `final_bet`** (ставки, reveal, +/− балів)
5. **Режим `wheel`** (зважене колесо, фільтрація)
6. **Режим `word_reveal`** + банки слів/термінів

MVP для першого тесту = пункти 1–3 (з ними вже можна ганяти keyboard наживо).

## 7. Що НЕ робити (щоб не роздувати)

- ❌ повноцінна автентифікація / реєстрація / БД юзерів — тільки ключ кімнати
- ❌ Postgres / зовнішня БД — снапшот у файл достатньо
- ❌ realtime там, де команди нічого не тиснуть (Paint, Хто я?, Поясни — офлайн, тільки таймер + слово)
- ❌ «Збери ПК» — прибрано
- ❌ автопідрахунок помилок keyboard як фінальне рішення — тільки підказка, затверджує ведучий
